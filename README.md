# SysChime

SysChime is a small Linux user daemon that turns important system conditions into persistent desktop alerts with configurable warning sounds.

Current built-in plugins:

- **Battery** — warning and critical thresholds while discharging.
- **Thermal** — sustained CPU, GPU, and NVMe temperature alerts with hysteresis.
- **VPN** — warns when a NetworkManager VPN that was connected becomes disconnected.

The alert engine is independent from the plugins. Each alert profile can use a different ringtone and sound behavior: `once`, `repeat`, `loop`, `interval`, or `none`.

## Requirements

- Linux with Python 3.11+
- D-Bus
- UPower for battery monitoring
- NetworkManager for VPN monitoring
- Linux `hwmon` sensors for thermal monitoring
- A desktop notification server implementing `org.freedesktop.Notifications` (for example dunst)
- One audio player: `pw-play` (preferred), `paplay`, `aplay`, or `ffplay`

Runtime Python dependency: `dbus-next`.

## Install

Recommended for a user-level utility:

```bash
cd ~/Repos/syschime
pipx install .
```

Copy the example configuration:

```bash
mkdir -p ~/.config/syschime
cp config.example.toml ~/.config/syschime/config.toml
syschime validate
```

Test hardware discovery and alert output before enabling the daemon:

```bash
syschime sensors
syschime test-sound warning-medium
syschime test-alert --sound warning-medium --mode once
```

## Run manually

```bash
syschime daemon
```

Use `--verbose` before the subcommand for debug logging:

```bash
syschime --verbose daemon
```

## systemd user service

The supplied unit assumes the `pipx` app shim exists at `~/.local/bin/syschime`.

```bash
mkdir -p ~/.config/systemd/user
cp systemd/syschime.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now syschime.service
```

Inspect it with:

```bash
systemctl --user status syschime.service
journalctl --user -u syschime.service -f
```

Disable it with:

```bash
systemctl --user disable --now syschime.service
```

## Battery behavior

Defaults:

- warning at **20%**
- critical at **10%**
- battery alerts only while discharging
- plugging in the charger immediately resolves the active battery alert
- warning escalates to critical without duplicate alerts
- warning/critical audio loops until the notification is acknowledged or the battery condition resolves

## Thermal behavior

SysChime reads `/sys/class/hwmon` and groups recognized sensors into CPU, GPU, and NVMe categories. If no NVIDIA GPU temperature is exposed through hwmon, it falls back to `nvidia-smi`. Only the hottest sensor in each category drives an alert, preventing one alert per CPU core.

Defaults use sustained thresholds rather than single-sample spikes. Example CPU defaults:

- warning: 90°C for 20 seconds
- critical: 97°C for 5 seconds
- recovery: 80°C

The recovery threshold provides hysteresis so the alert does not flap around the trigger temperature.

## VPN behavior

SysChime reads NetworkManager's active connections over the system D-Bus.

With `watch = []`, a VPN must first be observed as connected during the current SysChime process. A later transition to disconnected raises one alert. Startup while no VPN is connected does not alert.

To watch only specific NetworkManager connection names:

```toml
[plugins.vpn]
watch = ["HTB", "work-vpn"]
```

The current v0.1 polling implementation treats both manual and unexpected connected-to-disconnected transitions as disconnect events.

## Alert profiles and sounds

Built-in sounds:

- `warning-soft`
- `warning-medium`
- `warning-urgent`
- `warning-critical`
- `disconnect`
- `resolved`

These WAV files are generated by `tools/generate_sounds.py` and are original project assets.

Sound modes:

- `once` — play once
- `repeat` — play a configured number of times
- `loop` — continuously replay until acknowledgement/resolution
- `interval` — replay periodically while active
- `none` — notification only

A profile may also reference an absolute or `~`-relative custom sound file instead of a built-in name.

Example:

```toml
[alerts.profiles.vpn_disconnect]
severity = "warning"
sound = "~/Music/vpn-warning.wav"
mode = "once"
volume = 0.8
persistent = true
```

`pw-play`, `paplay`, and `ffplay` support the configured per-alert volume. `aplay` is a last-resort fallback and cannot apply per-alert volume itself.

## Development and tests

The state machines are deliberately isolated from hardware/D-Bus adapters, so logic can be tested without forcing battery, temperature, or VPN state changes.

Run all tests:

```bash
cd ~/Repos/syschime
PYTHONPATH=src python -m unittest discover -s tests -v
```

Regenerate built-in sounds:

```bash
python tools/generate_sounds.py
```

## Design boundary

v0.1 intentionally has no GUI, web server, remote notifications, generic scripting engine, or third-party plugin marketplace. The project currently focuses on reliable local system-condition alerts and keeps plugin logic separate from delivery logic so more monitors can be added later without duplicating notification/audio behavior.

### Audio troubleshooting

`test-sound` reports the detected command-line audio backends and the backend that actually succeeded:

```bash
syschime test-sound warning-medium
```

For backend failure details, put the global verbose flag before the subcommand:

```bash
syschime --verbose test-sound warning-medium
```

SysChime tries usable backends in this order: `pw-play`, `paplay`, `ffplay`, then `aplay`. A player merely being installed is not considered sufficient; if playback fails, SysChime tries the next available backend and reports all failures if none work.
